# ファームウェアとソフトウェアの先行検証計画

基板を発注する前に、デジタル側（TS の取り込み → FPGA での多重化 → FX3 → USB3 → ホスト）を市販の評価ボードで確かめておく。
目的は、v1 の基板で不具合が出たときに、原因を RF・アナログ側に絞り込める状態にすること（R-03 への対策）。

## 段階

| 段階 | 内容 | 必要なもの | 完了の条件 |
|---|---|---|---|
| S0 | 参照ボードで基準データを取る。px4_drv で受信し、TS ファイル、C/N、BER、レジスタ操作のログを記録する | DTV02A-4TS-P、Linux か Windows の PC | 地デジと BS の TS を各 1 分ずつ保存できた。px4_drv のデバッグログで I²C 操作の手順を記録できた |
| S1 | FX3 単体で USB3 転送を試す。GPIF II 同期スレーブ FIFO から USB3 バルク転送 IN へ流し、ホストは libusb で受け取る | FX3 評価ボード、FX3 SDK（ARM GCC） | テストパターンを毎秒 60MB 以上、取りこぼしなく受け取れる |
| S2 | FPGA の論理回路をシミュレーションで作る。シリアル TS 受信 ×4 → 系統タグ付け → 多重化 → FIFO | yosys、nextpnr、iverilog、cocotb（PC 上だけで完結する） | S0 で保存した TS を入力したとき、出力をホスト側で系統ごとに分け直すと、元のファイルと一致する |
| S3 | FPGA を評価ボードに載せ、FX3 とつなぐ。ジャンパ線なので 10〜25MHz の低いクロックで動かす | iCE40 評価ボード、FX3 評価ボード | FPGA が生成した TS 形式のテストパターンが、ホストで欠けずに受け取れる |
| S4（任意） | 参照ボードの TS を横取りする。CXD2856ER と IT9305E の間の TS 線 4 本に細い線をはんだ付けし、iCE40 評価ボードで受ける | measurement-procedure.md §2-2 で TS ピンを特定しておく | 本物の放送の TS を FPGA で受け取れる。**参照ボードを壊す危険がある** |
| S5 | ホスト側ドライバの骨組みを作る。px4_drv の cxd2856er.c と cxd2858er.c（GPLv2）をユーザー空間に移植し、I²C を差し替えられるようにする | — | 模擬の I²C で、選局時のレジスタ操作が S0 のログと一致する |

## リポジトリの構成

```
hw/       KiCad プロジェクト（v1 基板）
fpga/     iCE40 用の RTL、テストベンチ（cocotb）、ビルド（yosys/nextpnr）
fx3/      FX3 ファームウェア（GPIF II 設定、ベンダーリクエスト）
host/     libotr（デバイスの制御、TS の受け取りと分離）、otr-rec（recpt1 互換の CLI）、その後 BonDriver
docs/     設計資料
```

## 現在の実施範囲（D-28）

- **すぐ実施できる段階**
  - S0：完了（2026-11-01、docs/reference/s0-baseline.md）
  - S2：完了（2026-11-01）。実際の TS 4 系統でビット単位まで一致し、バッファが溢れたときの挙動も確認した。結果は fpga/README.md
  - S5：ホスト側ドライバの骨組みを作る
- **保留する段階**：S1、S3、S4。評価ボードを買うまで止める
- **買わないままの場合**：FX3 と FPGA の実機確認は v1 基板で初めて行うことになる（R-11）。v1 には次の 2 つを必ず用意しておく
  - FX3 と FPGA の間の信号を観測するテストポイント
  - FX3 を USB 起動で確実に立ち上げるためのジャンパ
