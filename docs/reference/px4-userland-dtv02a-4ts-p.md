# px4-userland v0.2.1 を DTV02A-4TS-P で動かした記録（2026-11-01 13:08〜13:20 JST）

目的：ホスト側を px4-userland（C++、GPLv2）の上に作る（D-40）前に、参照ボードと同じチップ構成（IT9305E、CXD2856ER×4、CXD2858ER×4）を、ユーザー空間から制御できることを確かめる。
px4-userland の対応表では、DTV02A-4TS-P（USB ID `0511:0254`）は「未検証」になっている。

## 環境と手順

- 実機は本番の vm110-rec（Ubuntu 26.04）。予約録画のない時間帯に行った。
- バイナリは `px4-userland-0.2.1-linux-musl-x86_64.tar.gz`。SHA256SUMS で照合した。
- ファームウェアは `/lib/firmware/it930x-firmware.bin`。SHA-256 は px4-userland の受理条件と一致した。
- 手順：
  1. Mirakurun を停止する。
  2. `px4_usb` から USB インターフェース `11-1:1.0` の割り当てを外す（unbind）。
  3. `px4d` を起動し、試験する。
  4. 割り当てを戻し（bind）、Mirakurun を再開する。
- 本番の停止時間：約 11 分。復旧後、Mirakurun で 4 チューナーとも `isAvailable=true`、`isFault=false` になったことを確認した。

## 結果

`px4ctl list` の出力：`receiver 0..3, device=1, system=ISDB-T/S`

### 1 受信機ずつ（各 8 秒）

| 受信機 | T27 | BS15_0 |
|---|---|---|
| 0 | 159,904 pkt | 129,717 pkt |
| 1 | 159,904 pkt | 129,716 pkt |
| 2 | 160,721 pkt | 129,718 pkt |
| 3 | 159,905 pkt | 129,717 pkt |

すべての組み合わせで、sync-errors、tei、continuity-errors、queue-drops、usb-errors が 0 だった。

### 4 受信機を同時に（各 10 秒）

| 受信機 | チャンネル | パケット数 | エラー |
|---|---|---|---|
| 0 | T27 | 201,391 | すべて 0 |
| 1 | T20 | 201,384 | すべて 0 |
| 2 | BS15_0 | 164,117 | すべて 0 |
| 3 | BS01_0 | 117,310 | すべて 0 |

- S0（px4_drv、チューナー #4）では、T20 で 20 秒に TEI が 5 個出ていた。今回の T20 は 10 秒で TEI 0。原因はまだ切り分けていない。
- 試験スクリプトの不具合（`wait` がバックグラウンドで動く px4d の終了まで待っていた）で、復旧が予定より約 8 分遅れた。px4-userland 側の問題ではない。

## 結論

- DTV02A-4TS-P は、px4-userland v0.2.1 で 4 受信機とも地上波・BS を受信でき、4 受信機の同時受信もできた。今回の試験範囲では問題がなかった。
- 確かめていないこと：長時間の連続受信、CS、内蔵カードリーダー、USB の抜き差しからの復旧。
- この結果を上流（Khronos31/px4-userland）に報告するかどうかは、ユーザーの判断を待つ。
