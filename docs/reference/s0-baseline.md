環境：本番の録画用 VM（vm110-rec、Ubuntu 26.04、px4_drv 0.7.0、recisdb 1.3.2）。DTV02A-4TS-P は USB パススルーで VM に渡されている（USB ID 0511:0254）。

## 未復号の TS（20 秒ずつ）

取得コマンドは `recisdb tune --no-decode --no-strip` で、復号もヌルパケットの除去もしていない。つまり、復調 IC が出力した TS とほぼ同じ形（ブリッジとドライバを通った後）になっている。
放送の内容を含むので、ファイルは公開リポジトリに入れない。保存先は `~/otr-data/s0-20261101/`（ローカルのみ）。

- 地デジのレート（ヌル込みで約 30Mbps）は、ISDB-T の TS 出力の上限（約 32.5Mbps）に近い。取得時間 20 秒には選局にかかる時間も含まれるので、その分だけ低く出ている。
- BS は、ドライバが TSID で 1 本に絞った後のレートになっている（トランスポンダ全体の約 52Mbps ではない）。
- **FPGA の設計値**：1 系統あたり最大で約 32.5Mbps（地デジ）。BS でトランスポンダ全体を出す設定なら約 52Mbps。4 系統合計で最大約 210Mbps。これは architecture.md の想定と一致する。

## 気づいたこと

- T20 は C/N が 26dB あるのに、20 秒で TEI が 5 パケット出た。送信側の要因か、チューナー #4 固有の問題かは未確認。他のチューナーと比べるのは、次に機会があるときにする。
- Mirakurun の `decode=0` を付けても、チューナー設定のコマンド（recisdb）の段階で復号されるので、未復号の TS は取れない。未復号の TS が必要なときは、空いているチューナーで recisdb を直接実行する。
- vm-rec では `localhost` が ::1（IPv6）に解決され、Mirakurun の API が応答しない。127.0.0.1 なら応答する。homelab-infra の手順書は `localhost` を使っているので、注意が必要。
