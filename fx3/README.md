# fx3

CYUSB3014 firmware: GPIF II slave FIFO to USB3 bulk IN; vendor requests for I2C (via TCA9546A), GPIO, and iCE40 SPI configuration.
License: MIT (see ../LICENSES). The FX3 SDK libraries are proprietary, so firmware binaries are subject to the Cypress/Infineon license terms.

## Build environment (Docker)

1. Download the FX3 SDK for Linux from Infineon (an account may be required). Extract the firmware package inside it (`fx3_firmware_linux.tar.gz`) so that `~/opt/fx3sdk` directly contains `fw_build/`, `fw_lib/`, and `firmware/`.
2. `docker build -t otr-fx3 fx3/docker`
3. `docker run --rm -v ~/opt/fx3sdk:/opt/fx3sdk:ro -v "$PWD/fx3":/work otr-fx3 make`

The SDK is mounted, never copied into the image or the repository, because it is not redistributable.

## SDK files and licensing

The firmware links against SDK files that are licensed by Cypress/Infineon and are not redistributable: `firmware/common/cyfx_gcc_startup.S`, `firmware/common/cyfxtx.c`, and the `fw_lib` libraries. They are referenced from `$FX3_INSTALL_PATH` at build time and are never copied into this repository. bladeRF's MIT-licensed FX3 firmware handles them the same way.
GPIF II configuration headers are generated by our own GPIF II Designer projects (a Windows-only tool), and only those generated files are committed.
`fx3/build.sh <dir>` builds a firmware directory and runs `elf2img`. It was verified with the SDK's slfifosync example on 2026-11-01.

## Firmware (`fw/`, MIT)

Written from scratch against the FX3 API guide. No SDK example code is copied (D-37). Build with `fx3/build.sh fx3/fw`, which produces `otr_fx3.img`. The image is used for USB RAM boot and also for the I2C boot EEPROM (D-46).

| File | Contents |
|---|---|
| `otr_fw.h` | Protocol v1 constants. Must stay in sync with otr-userland `src/fx3_protocol.h`. |
| `otr_board.h` | **Provisional** pin map (no schematic yet). Uses GPIO 33..45 (free with the 16-bit GPIF), SPI on 53..56, I2C on the dedicated pins. |
| `otr_main.c` | Clocks (SYS_CLK 403.2 MHz), IO matrix (`isDQ32Bit = CyFalse`, UART/I2C/SPI), application thread. |
| `otr_usb.c` | SS/HS/FS descriptors (vendor class, one interface, EP1 IN bulk with SS burst 16), BOS with the MS OS 2.0 platform capability, the MS OS 2.0 descriptor set (WINUSB + DeviceInterfaceGUIDs), and the vendor-request handler. |
| `otr_io.c` | GPIO, with safe defaults (channels off and in reset, LNB off) and LNB enable refused without DC input (D-30). The I2C program executor selects the TCA9546A channel and turns a short write followed by a read into a repeated start. Also the boot EEPROM page write/read. |
| `otr_fpga.c` | iCE40 SPI slave configuration (CRESET_B, 1.5 ms, bitstream, dummy clocks, CDONE) and the FPGA register framing over SPI. |
| `otr_stream.c` | PIB/GPIF load, a DMA AUTO channel (PIB socket 0 to EP1 IN, 4 x 16 KiB), start/stop. |

Status (2026-11-01): the firmware builds warning-free with `-Wall -Werror` (image 142 KB), and the descriptor sizes were checked against their declared lengths. It has **not run on hardware**.

Until `fx3/gpif/cyfxgpif2config.h` is generated (D-41), the build uses the SDK sync slave FIFO example configuration in 16-bit mode, read from the SDK tree. Still open:
- The FPGA-side SPI register block that FPGA_REG talks to.
- The partial-buffer flush on stream stop.
- A per-board serial number.
